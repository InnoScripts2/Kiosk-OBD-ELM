### 5a. Thickness QR Payment Screen
**Компонент**: `PaymentQRScreen.kt`  
**ViewModel**: `PaymentViewModel.kt`

**Содержимое**:
- QR-код (центр, крупный)
- Текст: "Отсканируйте QR для оплаты"
- Сумма оплаты
- Таймер обратного отсчёта (10 минут)
- Прогресс-бар (зелёный → красный при < 2 минут)
- В DEV: кнопка "[DEV MODE] Подтвердить"
- Кнопка "Отмена" (всегда доступна)
- Индикатор "[MOCK MODE] Режим разработки" (только при PAYMENT_MOCK=true)

**Состояния**:
- `Idle` — начальное состояние
- `CreatingIntent` — создание платёжного интента
- `Processing` — ожидание оплаты (показ QR, таймер)
- `Completed` — оплата подтверждена
- `TimedOut` — таймаут 10 минут истёк
- `Cancelled` — отменено пользователем
- `Error` — ошибка обработки платежа

**Логика**:
- PaymentStatusPoller опрашивает статус каждые 2 секунды
- PaymentStatusReducer предотвращает двойные эмиты
- Таймаут 10 минут строго соблюдается
- Кнопка "Подтвердить" доступна только при BuildConfig.PAYMENT_MOCK=true
- Автоматические переходы при Completed/TimedOut

**Переходы**:
- Платёж подтверждён → Prepare Device Screen
- Таймаут 10 минут → Service Selection Screen
- Отмена → Service Selection Screen

**DEV-кнопка**: "[DEV MODE] Подтвердить" (вызывает PaymentViewModel.confirmPaymentDev(), доступна только при APP_MODE=DEV)

### 8a. Measurements Screen
**Компонент**: `ThicknessMeasurementsScreen.kt`

**Содержимое**:
- Сетка 40-60 полей (зоны кузова)
- Каждое поле:
  - Название зоны (Капот, Крыша, и т.д.)
  - Текущее значение (получается через ThicknessDevice)
  - Статус: пусто / измеряется / заполнено
- Общий прогресс: "N из 60 замеров"
- Кнопка "Завершить измерения" (активна после всех замеров)

**Логика**:
- Подключение к ThicknessDevice через BLE

**Переходы**:

## DEV-режим

### Активация
Переменная `APP_MODE=DEV` в `.env`.

### Кнопка "Пропустить"
- Видна только в DEV-режиме
- Расположение: правый верхний угол экрана
- Цвет: полупрозрачный серый (чтобы не мешать)
- Текст: "[DEV] Пропустить"
- Действие: переход к следующему экрану с автозаполнением

### Имитация оплаты
- QR Payment экраны в DEV показывают кнопку "Имитация оплаты"
- При нажатии вызывается `PaymentService.confirmPayment(intentId)`
- Имитация задержки: 1-2 секунды
- Переход к следующему экрану

### Имитация устройств
Если `DEVICE_MOCK_OBD=true` или `DEVICE_MOCK_THICKNESS=true`:
- ThicknessDevice возвращает случайные значения 100-150 мкм
- ObdDevice возвращает 2-3 тестовых DTC
- Соединение всегда успешно (задержка 1 сек)

**ВАЖНО**: В production (APP_MODE=PROD) все кнопки "Пропустить" и моки полностью отключены (не компилируются).

## Guard Conditions (Правила переходов)

1. **Валидация данных**:
   - Email: содержит @
   - Телефон: минимум 10 цифр
   - Кнопка "Далее" неактивна до валидации

2. **Оплата**:
   - Переход возможен только после `payment.status === 'confirmed'`
   - Таймаут 10 минут → отмена сессии

3. **Устройства**:
   - Таймаут соединения: 5 сек
   - Таймаут измерения: 30 сек на точку
   - При ошибке → возврат к Service Selection с сообщением

4. **Авто-сброс**:
   - Бездействие 5 минут → Attract Screen
   - После отправки отчёта: 30 сек → Attract Screen

## Сессия и состояние

### Session Model
```kotlin
data class KioskSession(
    val id: String,
    val type: ServiceType, // THICKNESS | DIAGNOSTICS
    val timestamp: Long,
    val phone: String,
    val email: String,
    val vehicleType: String?, // для толщиномера
    val vehicleBrand: String?, // для диагностики
    val paymentIntentId: String?,
    val status: SessionStatus // STARTED | PAYMENT_PENDING | IN_PROGRESS | COMPLETED | CANCELLED
)
```

### SessionManager
- Создание сессии
- Обновление статуса
- Таймауты
- Авто-сброс
- Логирование
