### Причины блокировки

1. **Сетевая изоляция**: 
   - Среда выполнения не имеет доступа к `dl.google.com`

2. **Отсутствие AGP в публичных репозиториях**:
   - Maven Central: только AGP ≤2.3.0
   - Gradle Plugin Portal: AGP не публикуется там
   - AGP доступен ТОЛЬКО в Google Maven

3. **Пустой локальный кэш**:
   - `~/.gradle/caches/` не содержит AGP 8.4.1
   - Нет pre-downloaded артефактов

### Детали стратегий

#### Стратегия A: Корпоративный прокси

**Суть**: Настроить HTTP/HTTPS прокси для доступа к Google Maven

**Требования**:
- Прокси-сервер с whitelist для `dl.google.com`
- Учётные данные (опционально)
- Настройка `~/.gradle/gradle.properties`:
  ```properties
  systemProp.http.proxyHost=proxy.company.com
  systemProp.http.proxyPort=8080
  systemProp.https.proxyHost=proxy.company.com
  systemProp.https.proxyPort=8080
  ```

**GitHub Secrets** (если используется CI/CD):
- `PROXY_HOST`
- `PROXY_PORT`
- `PROXY_USER` (опционально)
- `PROXY_PASSWORD` (опционально)

**Преимущества**:
- ✅ Доступ ко всем версиям AGP
- ✅ Полная совместимость
- ✅ Можно использовать любые Google сервисы

**Недостатки**:
- ❌ Требуется корпоративная инфраструктура
- ❌ Управление секретами
- ❌ Зависимость от прокси

#### Стратегия B: Локальное зеркало Maven (Nexus)

**Суть**: Развернуть Nexus Repository Manager и загрузить AGP вручную

**Требования**:
- Сервер: 4GB RAM, 50GB storage
- Docker или VM
- Ручная загрузка артефактов AGP

**Настройка Nexus**:
1. Развернуть через Docker Compose
2. Создать proxy repository для Google Maven
3. Создать hosted repository для ручной загрузки
4. Создать group repository

**Настройка Gradle** (`android/settings.gradle.kts`):
```kotlin
pluginManagement {
    repositories {
        maven { 
            url = uri("http://<nexus>:8081/repository/maven-public/")
            credentials {
                username = System.getenv("NEXUS_USERNAME")
                password = System.getenv("NEXUS_PASSWORD")
            }
        }
    }
}
```

**Преимущества**:
- ✅ Полный контроль над артефактами
- ✅ Быстрая загрузка (локальная сеть)
- ✅ Независимость от внешних сервисов

**Недостатки**:
- ❌ Высокая сложность
- ❌ Требуется обслуживание
- ❌ Затраты на инфраструктуру

#### Стратегия C: Downgrade AGP

**Суть**: Понизить AGP до версии, доступной в Maven Central (≤2.3.0)

**Анализ совместимости**:

| Компонент | Текущее | Требует AGP | Доступна AGP | Совместимость |
|-----------|---------|-------------|--------------|---------------|
| compileSdk | 35 | ≥8.1.0 | ≤2.3.0 | ❌ |
| Kotlin | 1.9.24 | ≥7.3.0 | ≤2.3.0 | ❌ |
| Gradle | 8.7 | ≥8.0.0 | ≤2.3.0 | ❌ |
| Jetpack Compose | Да | ≥7.0.0 | ≤2.3.0 | ❌ |

**Вывод**: ❌ **НЕ РАБОТАЕТ** - полная несовместимость

**Статус**: ОТКЛОНЕНО

#### Стратегия D: GitHub-hosted runner

**Суть**: Использовать стандартные GitHub-hosted runners с доступом к dl.google.com

**Требования**:
- Разрешение использовать `ubuntu-latest` (GitHub-hosted)
- Или whitelist для `dl.google.com` в организации

**Конфигурация** (`.github/workflows/android-build.yml`):
```yaml
jobs:
  build:
    runs-on: ubuntu-latest  # GitHub-hosted runner
    steps:
    - uses: actions/checkout@v4
    - name: Set up JDK 17
      uses: actions/setup-java@v4
      with:
        distribution: 'temurin'
        java-version: '17'
    - name: Build
      run: cd android && ./gradlew assembleDebug
```

**Преимущества**:
- ✅ Минимальные изменения
- ✅ Стандартный подход
- ✅ Нет дополнительной инфраструктуры

**Недостатки**:
- ❌ Зависимость от политик организации
