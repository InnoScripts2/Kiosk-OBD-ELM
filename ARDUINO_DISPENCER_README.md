# Arduino Dispencer - Документация прошивки

## Обзор

Arduino-скрипт `dispencer.ino` управляет электронными замками для выдачи устройств (толщиномер и OBD-адаптер) в киоске самообслуживания.

## Требования к оборудованию

### Компоненты

1. **Микроконтроллер**: Arduino Uno/Nano/Mega
2. **Реле**: 2× модуля реле 5V (для управления замками)
3. **Датчики**: 2× герконы или концевые выключатели (обратная связь о положении)
4. **Замки**: 2× электромагнитные замки 12V
5. **Питание**: Блок питания 12V/2A для замков
6. **Провода**: Соединительные провода, резисторы pull-up если требуется

### Схема подключения

```
Arduino Pin    | Устройство                    | Описание
---------------|-------------------------------|----------------------------------
PIN 2          | Реле #1 (IN)                  | Управление замком толщиномера
PIN 3          | Датчик #1 (геркон)            | Положение замка толщиномера
PIN 4          | Реле #2 (IN)                  | Управление замком OBD-адаптера
PIN 5          | Датчик #2 (геркон)            | Положение замка OBD-адаптера
PIN 13         | Встроенный LED                | Индикация активности
GND            | Реле (GND), Датчики (GND)     | Общий провод
5V             | Реле (VCC)                    | Питание реле
12V External   | Замки                         | Питание электромагнитных замков
```

### Логика датчиков положения

- **LOW (0V)**: Замок закрыт (нормальное состояние)
- **HIGH (5V)**: Замок открыт (устройство может быть извлечено)

Датчики подключаются с внутренними pull-up резисторами Arduino (`INPUT_PULLUP`).

## Протокол связи

### Параметры Serial

- **Скорость**: 9600 baud
- **Формат**: 8N1 (8 бит данных, без паритета, 1 стоп-бит)
- **Окончание команды**: `\n` (новая строка)
- **Кодировка**: ASCII

### Команды

#### OPEN_THICKNESS
Открыть замок толщиномера.

**Запрос**: `OPEN_THICKNESS\n`

**Ответы**:
- `OK:OPENED:THICKNESS\n` - замок успешно открыт
- `OK:ALREADY_OPEN:THICKNESS\n` - замок уже открыт
- `ERROR:BUSY:THICKNESS\n` - замок занят другой операцией
- `ERROR:TIMEOUT:THICKNESS\n` - таймаут открытия (5 сек)
- `ERROR:HARDWARE:THICKNESS\n` - аппаратная ошибка

#### OPEN_OBD
Открыть замок OBD-адаптера.

**Запрос**: `OPEN_OBD\n`

**Ответы**: аналогично `OPEN_THICKNESS`, но с `OBD` вместо `THICKNESS`

#### CLOSE_THICKNESS
Закрыть замок толщиномера.

**Запрос**: `CLOSE_THICKNESS\n`

**Ответы**:
- `OK:CLOSED:THICKNESS\n` - замок успешно закрыт
- `OK:ALREADY_CLOSED:THICKNESS\n` - замок уже закрыт
- `ERROR:TIMEOUT:THICKNESS\n` - таймаут закрытия (5 сек)

#### CLOSE_OBD
Закрыть замок OBD-адаптера.

**Запрос**: `CLOSE_OBD\n`

**Ответы**: аналогично `CLOSE_THICKNESS`

#### STATUS
Запросить текущий статус всех замков.

**Запрос**: `STATUS\n`

**Ответ**: `STATUS:THICKNESS=CLOSED,OBD=CLOSED\n`

Возможные значения: `OPEN`, `CLOSED`

#### PING
Проверка связи (heartbeat).

**Запрос**: `PING\n`

**Ответ**: `PONG\n`

### Логирование

Все операции логируются в формате:
```
[LOG] <timestamp_ms> <operation> <lock_name>
```

Примеры:
```
[LOG] 12345 OPEN_START THICKNESS
[LOG] 12850 OPENED THICKNESS
[LOG] 22850 AUTO_CLOSE THICKNESS
[LOG] 23400 CLOSED THICKNESS
```

## Механизмы безопасности

### 1. Автоматическое закрытие
Если замок остаётся открытым более **10 секунд**, он автоматически закрывается для предотвращения несанкционированного доступа.

### 2. Watchdog таймер
Если связь с управляющим компьютером прерывается более чем на **60 секунд**, все открытые замки автоматически закрываются.

### 3. Блокировка повторных команд
Пока замок выполняет операцию открытия/закрытия, новые команды для этого замка отклоняются с ответом `ERROR:BUSY`.

### 4. Таймауты операций
Каждая операция открытия/закрытия имеет таймаут **5 секунд**. Если за это время датчик положения не подтверждает изменение состояния, операция завершается с ошибкой.

### 5. Восстановление после ошибок
При возникновении ошибки замок переходит в состояние `LOCK_ERROR` на 5 секунд, после чего автоматически пытается вернуться в состояние `LOCK_CLOSED`.

## Конфигурация Node.js агента

### Переменные окружения (.env)

```bash
# Arduino Serial порт
ARDUINO_PORT=/dev/ttyUSB0        # Linux
# ARDUINO_PORT=COM3              # Windows
# ARDUINO_PORT=/dev/cu.usbserial # macOS

# Скорость Serial порта
ARDUINO_BAUD=9600

# Таймауты (миллисекунды)
ARDUINO_COMMAND_TIMEOUT=10000    # Таймаут выполнения команды
ARDUINO_RECONNECT_DELAY=5000     # Задержка переподключения
```

### Интеграция с LockController

LockController должен:

1. **Инициализация**: Подключиться к Arduino через Serial порт при запуске
2. **Heartbeat**: Отправлять `PING` каждые 30 секунд для проверки связи
3. **Обработка команд**: Отправлять команды `OPEN_*` / `CLOSE_*` и ожидать подтверждения
4. **Обработка ответов**: Парсить ответы формата `OK:*` / `ERROR:*`
5. **Повторные попытки**: При таймауте или ошибке повторять команду до 3 раз
6. **Логирование**: Записывать все операции с timestamp и sessionId

## Тестирование

### Ручное тестирование через Serial Monitor

1. Открыть Arduino IDE > Tools > Serial Monitor
2. Установить скорость 9600 baud
3. Отправить команды:

```
PING
STATUS
OPEN_THICKNESS
STATUS
CLOSE_THICKNESS
STATUS
```

### Тестирование через Node.js

Создать файл `test-arduino.js`:

```javascript
import { SerialPort } from 'serialport';
import { ReadlineParser } from '@serialport/parser-readline';

const port = new SerialPort({ 
  path: '/dev/ttyUSB0', 
  baudRate: 9600 
});

const parser = port.pipe(new ReadlineParser({ delimiter: '\n' }));

parser.on('data', (line) => {
  console.log('Arduino:', line);
});

// Отправка команды после подключения
setTimeout(() => {
  port.write('PING\n');
  setTimeout(() => port.write('STATUS\n'), 1000);
  setTimeout(() => port.write('OPEN_THICKNESS\n'), 2000);
}, 2000);
```

Запустить:
```bash
npm install serialport @serialport/parser-readline
node test-arduino.js
```

### Unit-тесты LockController

Тесты должны покрывать:

1. Успешное открытие/закрытие замков
2. Обработка таймаутов
3. Обработка ошибок
4. Повторные попытки при сбоях
5. Heartbeat и восстановление связи

### Интеграционные тесты

Тесты с виртуальным Serial портом:

```bash
# Linux: socat для создания виртуальных портов
socat -d -d pty,raw,echo=0 pty,raw,echo=0
# Использовать созданные /dev/pts/X для Arduino и Node.js
```

## Диагностика проблем

### Arduino не отвечает

1. Проверить подключение USB кабеля
2. Проверить, что Arduino IDE видит устройство (Tools > Port)
3. Проверить, что скорость Serial порта совпадает (9600)
4. Перезагрузить Arduino (нажать кнопку RESET)
5. Проверить логи через Serial Monitor

### Замок не открывается

1. Проверить напряжение питания замков (должно быть 12V)
2. Проверить подключение реле (LED на модуле реле должен загораться)
3. Проверить датчик положения (мультиметром измерить напряжение)
4. Проверить логи Arduino через Serial Monitor
5. Послать команду `STATUS` для проверки текущего состояния

### Таймауты операций

1. Проверить физическое состояние замка (не заклинило ли механизм)
2. Проверить датчик положения (правильно ли он установлен)
3. Увеличить `LOCK_TIMEOUT` в коде Arduino (по умолчанию 5000 мс)
4. Проверить питание (недостаточное напряжение может замедлять работу)

### Watchdog закрывает замки

1. Проверить стабильность Serial соединения
2. Проверить, что Node.js агент отправляет регулярные heartbeats
3. Увеличить `WATCHDOG_TIMEOUT` в коде Arduino (по умолчанию 60000 мс)
4. Проверить логи Node.js агента на предмет ошибок подключения

## Обслуживание

### Плановое обслуживание

- Проверять надёжность Serial соединения раз в неделю
- Проверять работу замков и датчиков раз в месяц
- Очищать контакты реле раз в квартал
- Заменять изношенные механические части замков по необходимости

### Обновление прошивки

1. Скачать новую версию `dispencer.ino`
2. Открыть в Arduino IDE
3. Подключить Arduino по USB
4. Выбрать правильную плату и порт (Tools > Board, Tools > Port)
5. Загрузить прошивку (Sketch > Upload)
6. Проверить работу командой `PING` через Serial Monitor
7. Протестировать все команды перед вводом в эксплуатацию

### Логирование и мониторинг

Node.js агент должен:

1. Записывать все операции с замками в структурированные логи
2. Отслеживать количество ошибок и таймаутов
3. Отправлять алерты при превышении порогов ошибок
4. Сохранять статистику операций для анализа надёжности
