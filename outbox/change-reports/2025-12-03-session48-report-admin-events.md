# Change Report — 03.12.2025 (Session 48 — Report telemetry in Admin Bridge)

## Цели

- Прокинуть ключевые события генерации и доставки отчётов в Admin Bridge, чтобы будущие Windows/Android панели видели ход операций в реальном времени.
- Зафиксировать источник и канал отправки (SMS/email), статус предпросмотра и ошибки контактов прямо в журнале событий adminbridge:event.
- Устранить зависимость логики предпросмотра от активного экрана, передавая контекст услуги и контактов в модальное окно.

## Действия

1. `platform/ui/web/kiosk-frontend/index.html`:
   - Добавлены вспомогательные функции `normalizeReportKind` и `emitReportAdminEvent`, формирующие сообщения `Отчёт толщиномера/диагностики` с деталями (ID, канал, причина, текст ошибки).
   - `maybeSendReport` теперь логирует отсутствие контакта, нехватку данных, сетевые ошибки и успешную генерацию (вместе с ID отчёта); `openReportPreview` требует `info.id`, подставляет тип услуги, фиксирует событие «предпросмотр открыт» и публикует его во внешний поток.
   - Кнопки предпросмотра на финальных экранах передают `kind`, а закрытие модалки записывает событие «предпросмотр закрыт пользователем». Кнопка «Пропустить отправку» логирует предупреждение с причиной `skip-send`.
   - Кнопки отправки SMS/email используют `lastPreview.kind`, записывают события об успешной доставке (канал, ID) и об ошибках (API/сеть). Повторные ошибки сети конвертируются в события `recordAdminEvent` с severity `error`.
   - `lastPreview` сбрасывается при закрытии модалки, чтобы не сохранять устаревшие контакты, а все коды вызова `openReportPreview` теперь передают `kind`, что исключает необходимость вычислять тип по активному экрану.

2. Build: `npm run build` (см. ниже) подтвердил отсутствие регрессий.

## Команды
