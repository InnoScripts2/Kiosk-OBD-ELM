# payment-mock-kit

Мок-сервис платежей для DEV режима. Перенесён из `packages/payment-mock` в рамках Волны D миграции (Session 19G).

## Происхождение
- **Исходный путь**: `packages/payment-mock/`
- **Дата переноса**: 24.11.2025
- **Сессия**: 19G
- **Статус исходного каталога**: UTILIZED (помечен для удаления после подтверждения)

## Структура
Содержит минимальную заглушку для имитации платёжных операций в DEV режиме (package.json).

## Назначение
- **DEV режим**: Имитация подтверждения платежа через 2 секунды после создания intent
- **QA/PROD режимы**: Этот пакет не используется; применяется интеграция с реальным провайдером (Yandex.Kassa, Stripe)

## Связь с модулями
- Используется в `android/feature-payments` для тестирования платёжных потоков без реального провайдера
- Интерфейсы: `createPaymentIntent`, `getStatus`, `confirm`
- Генерирует фейковые QR-коды и webhook callbacks

## Безопасность
- **ВАЖНО**: Мок-режим должен быть явно запрещён в production конфигурации
- Флаг `PAYMENT_MOCK=true` должен проверяться перед каждым вызовом
- Все моковые операции логируются с пометкой `[MOCK MODE]`
- Никогда не имитировать реальные данные карт или персональную информацию

## Планируемая интеграция
После завершения миграции TypeScript пакетов, логика может быть адаптирована в Kotlin или использоваться напрямую через Node-агент для UI тестирования.

## Использование
```bash
# Из корня репозитория
cd android/feature-payments/payment-mock-kit
npm install
npm test
```

## Vault и секреты
- Мок не использует реальные секреты
- Для настоящих платежей см. `plan-secrets-config.md` и `credential-inventory.md`
- Vault пути: `kv/selfservice/platform/yookassa/{env}/` для production
