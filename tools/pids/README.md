# PID Catalog Builder

Скрипт `build_catalog.py` объединяет текущий каталог PID (`feature-obd-core/.../pids/pids.json`) с донорскими JSON-файлами из проекта AndroidOBD. В результате библиотека `feature-obd-core` получает расширенный набор PID с базовыми диапазонами, формулами и единицами измерения для веб‑словаря и автоматически публикует файлы `pids-mode{1,4,9}-v2.json` с новой схемой (mode/pid/bytes/range/sources) для Kotlin-бэкенда.

## Источники данных
- **Базовый каталог** — существующий `pids.json`, в котором уже заданы минимальные описания SAE PID.
- **Донор** — файлы `pids-mode1.json`, `pids-mode4.json`, `pids-mode9.json` (по умолчанию берутся из `../AndroidOBD-main/AndroidOBD-main/obd/src/main/assets`).

При объединении скрипт:
1. Нормализует `mode`/`pid` до шестнадцатеричного формата `0xNN`.
2. Конвертирует числовые диапазоны и формулы, добавляет дефолтный опросный интервал (1s для Mode 01, 2s для Mode 04, 10s для Mode 09).
3. Помечает каждую импортированную запись тегом `Dataset: AndroidOBD`, чтобы видеть происхождение данных.
4. Дополняет существующие записи только теми полями, которых не было (min/max/unit/formula/pollIntervalMs), сохраняя ручные заметки.

## Запуск
```powershell
cd android
python .\tools\pids\build_catalog.py
```
Дополнительные параметры:
- `--donor <путь>` — альтернативный каталог с `pids-mode*.json`.
- `--output <файл>` — явное расположение итогового `pids.json` (по умолчанию файл в `feature-obd-core`).
- `--existing <файл>` — база для мерджа (по умолчанию тот же файл, что и `--output`).
- `--v2-dir <путь>` — директория, куда сохраняются `pids-mode1-v2.json`, `pids-mode4-v2.json`, `pids-mode9-v2.json`.

Скрипт атомарно перезаписывает файл через временный `.tmp` и печатает количество объединённых PID.
